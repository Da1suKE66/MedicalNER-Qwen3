## 已修复的确定性缺陷

1. 修复后文本被训练重分批误存为`original_spans`。G1有200行、G2有700行、G5有126行、G6有700行受影响；新G1/G2/G3/G4/G5版本均为0。逐行验证prompt/completion/sample_weight不变，因此不把追溯修复说成模型精度提升。
2. 严格证据列表检查没有要求每个片段都存在。已修复并测试；实际当前源数据没有列表证据，不能用它解释全部历史低精度。
3. 新增独立G7：只对疾病名尝试字母间逗号差异的定位，不改评分、不合并同义词、不忽略否定/数字/其他标点。训练正标签4779→4887；这是候选覆盖变化，不是模型F1。
4. DPO关闭默认512-token输入截断；完整检查两偏好序列。GRPO为输入预留完整生成长度，失败时拒绝训练。
5. 真实DPO初始化检查发现第二适配器经过临时BF16复制后再升精度，504个张量与原SFT不同。使用同一检查点进行最多一次额外加载恢复逐位一致，不放宽一致性校验。
6. 真实GRPO首次16次rollout成功，但TRL0.23.1恢复reentrant检查点时缺少输入激活梯度，第一次反向传播失败。显式匹配reentrant模式并启用输入激活梯度，仍冻结基础模型参数；独立版本重跑。
7. DPO/GRPO随后均完成两步真实更新，但旧终端校验把Trainer的BF16自动混合精度前向与普通推理前向比较，分别误报0.671875/0.6875差异。独立GPU复现实验确认：保存权重与训练结束时记录的指纹逐位一致；移除包装后，两种模式的普通推理重载差异均为0。正式修复增加权重指纹检查并统一推理方式，不放宽0.02阈值。旧失败记录全部保留；不把两步验收当成完整RL评测。

修复依据包括已安装版本的源码与[Accelerate 1.10.1官方接口说明](https://huggingface.co/docs/accelerate/v1.10.1/en/package_reference/accelerator#accelerate.Accelerator.unwrap_model)。移除包装仅在训练结束后执行，不能在后续反向传播之前随意调用。

## 错误实体训练

保留全部1475条G1干净训练序列，新增164/492条含错误实体的副本，分别占最终序列约10%/25%。这些百分比不是实体、关系或token的比例。

错误实体在grounding之后进入实际模型prompt；所有关联它的目标关系为空，其他正确关系/证据不变；有正关系的副本不能全部变成空关系。噪声标记不进入prompt。真实同义词、粒度差异、漏标、单纯类型争议不自动当负例。

这是“制造的无原文支持名称”基础对照，尚不代表真实医学错误实体分布。正常推理仍执行grounding；后续需要独立的grounded干扰实体/人工复核真实预测错误对照。64对固定held-out clean/noise压力输入与训练组隔离，不用于选checkpoint。

减少连环错误分三层处理：名称/类型/原文片段进入关系输入，不只给实体ID；候选定位与关系证据检查限制无依据连边；错误实体负例学习拒绝连接。它们主要控制假阳性，不能凭空恢复漏掉的实体。G0固定预测实体候选只覆盖120/638条金标关系，18.81%是该条件下严格关系召回的上限，不是F1上限。因此实体漏检与命名粒度也必须独立改进；G7先检验有限的定位修复，不自动合并所有同义疾病。

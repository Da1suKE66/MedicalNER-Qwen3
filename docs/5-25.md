# MedicalNER-Qwen3 项目进展汇报

日期：2026-05-25

## 概览

本阶段完成了两个主要进展：

1. 在昇腾 NPU 环境上跑通了 Qwen3-8B 的 LoRA 训练，并把 `cutoff_len` 从此前 GPU 实验中的 2048 提升到 16384，基本解决了 5-12 汇报中提到的大量 CoT 序列被截断的问题。
2. 基于训练出的 adapter 做了两轮预测：第一轮先做 20 条样本的初步生成检查，确认模型整体能跟随医学 KG 抽取格式，不再出现大规模跨主题发散；第二轮构建了一个覆盖不同长度和复杂度的 20 条筛选测试集，并在该测试集上完成了一轮生成评估。

需要注意的是：当前预测评估仍然是初步结果。BLEU / ROUGE 可以反映文本相似度，但还不能等价为 KG 抽取质量；严格 JSON 可解析率、实体/关系覆盖率和幻觉检查仍需要进一步专项评估。

### 与 5-12 结果对比

5-12 的 GPU 训练受 24GB 显存限制，只能使用 `cutoff_len=2048`，导致 858 条样本中约 60.8% 被截断。当前 NPU 训练使用 `cutoff_len=16384`，可以覆盖几乎全部训练样本的完整 prompt + CoT + KG JSON，训练目标比之前完整得多。

| 实验 | 硬件 / 设置 | `cutoff_len` | 最优 eval loss | 主要限制 |
|------|-------------|--------------|----------------|----------|
| 5-12 GPU baseline | 24GB GPU，QLoRA | 2048 | 0.6485 | 大量 CoT response 被截断 |
| 5-25 NPU 训练 | 昇腾 NPU，LoRA bf16 | 16384 | 0.08405 | 预测阶段长文本仍有生成稳定性问题 |

结论：训练链路已经跑通，并且 NPU 长上下文训练显著缓解了此前的截断瓶颈。下一阶段的主要瓶颈从“训练能否覆盖完整样本”转移到了“生成阶段能否稳定输出完整、可解析、低幻觉的 KG JSON”。

定性观察：

- 输出整体仍围绕输入疾病、症状、诊断标准和关系组织，没有看到此前那种大规模跨主题幻觉。

- 长文本样本仍容易出现输出过长、重复片段、未闭合 `</output>` 或 JSON 不完整的问题。
- 因此，当前模型已经具备可用的 KG 抽取雏形，但还不能直接进入自动化批量生产，需要先加强格式约束和长文本生成策略。

## 4. 第二轮预测：筛选测试集生成

第二轮预测输出目录：

`models/predict/qwen3-8b-cot-pro858-kgtest20-npu/`

| 指标 | 数值 |
|------|------|
| 样本数 | 20 |

| ROUGE-1 | 50.90 |
| ROUGE-2 | 36.24 |
| ROUGE-L | 33.13 |
| 预测耗时 | 22406.14s，约 6h 13m 26s |
| 严格 JSON 可解析输出 | 9 / 20 |
| 标题完全匹配 | 7 / 20 |

这组筛选测试集比第一轮初步检查更难，因为它有意包含了长文本和高复杂度样本。主要观察如下：

- 极短样本的结构基本合理。例如，模型可以从短的 withdrawal 或 secondary syndrome 标题中识别疾病和症状。
- 相比之前，模型不太容易生成完全无关的医学内容，说明 adapter 已经学习到 KG 抽取任务的基本格式。
- 属性级幻觉仍然存在。典型模式是：gold 输出中某些属性为空，但模型可能主动补入 DSM code、subtype 等信息。
- 随着输入长度和 KG 复杂度增加，完整性下降明显。长样本经常出现未闭合 `<output>`、重复短语、或者只生成部分 JSON 的问题。
- 这组高难度测试集上的严格 JSON 可解析率只有 9 / 20，因此下一步评估不能只依赖 BLEU / ROUGE。需要单独做 KG 级评估，分别衡量 JSON 有效性、实体覆盖、关系覆盖、证据一致性和 unsupported fields。

## 5. 当前结论

最重要的结果是：已经在 NPU 上成功跑通了长上下文训练。相比 5-12 的设置，当前训练目标更接近真实任务，因为模型可以看到接近完整的 CoT 和 KG JSON 标注。

预测质量已经能说明模型在学习抽取格式，并且不再大规模生成无关内容。但目前主要瓶颈仍然在生成阶段：

- 长输入会触发重复生成或不完整 JSON。
- 严格 JSON 输出还不够稳定，暂时不能直接用于自动化下游流程。
- BLEU / ROUGE 可以作为第一信号，但不足以评价 KG 抽取质量。
- 筛选测试集很有价值，因为它暴露了短样本中不明显的长文本和高复杂度失败模式。

## 下一步计划

1. 构建面向 `generated_predictions.jsonl` 的 KG 级评估脚本：JSON 有效性、实体 precision / recall、关系 precision / recall、证据支撑情况，以及 unsupported property 检测。
2. 加强生成阶段的格式控制：缩短 CoT、设置更严格的 stop criteria、增加 JSON repair / validation pass，或者在 thinking 部分后只解码最终输出。
3. 对长疾病综述页面采用 chunk-and-merge 策略，而不是要求模型一次性生成一个很大的 KG。
4. 使用 `kg_review_viewer.html` 人工 review 20 条筛选测试样本，标注医学准确性、KG 完整性和幻觉模式。
5. 格式稳定性改善后，重新跑筛选测试集，并与当前 `qwen3-8b-cot-pro858-kgtest20-npu` baseline 对比。

## 交付物与完成条件

最终必须交付一个可加载的实体 adapter、一个选定的关系 adapter、确定的推理/规则配置、从原始文本到图的统一命令，以及完整评测报告。若采用 GRPO，另保存其 SFT 起点与加载链。私有数据、原始生成、权重保存在本地私有目录和用户授权服务器；GitHub 只提交代码、配置、测试和聚合结果。

完成意味着：足量训练、完整数据评测、可复现的最终模型和错误分析均完成。不能用 loss、奖励、2-step smoke、少数案例或单一 oracle 数字替代。效果没有改善时必须保留负结果并选用实际更好的方案；不能承诺或编造一个尚未测得的 F1。

## 已确认的工程依赖

- 当前新 relation 入口 `generative.evaluate` 接受预测实体 cache，且明确标记 `not_full_live_pipeline=True`。旧 `run_pipeline --relation-adapter` 使用另一套 prompt/parser，不能直接挂本轮 adapter 当作新全流程。
- 迁移包未包含实体 checkpoint。旧 entity v4 训练数据有 119 行/69 条记录来自内部 tune，因此必须按冻结 source/group 重新生成 train-only 实体数据并完整重训。
- 原文首次出现顺序、4 对短输出和 local 句窗在 `generative.protocol` 已有实现，但 `launch_release.py` 目前只发布 base；新臂必须重建目标、UNKNOWN mask 和负例来源，不能只改推理参数。
- `release_v2.build_rows` 会删除无正例行。改顺序或重新分批后可能改变实际监督覆盖；必须逐个原子 decision/正边/证据比对，并为可靠全负序列增加明确保留路径。
- DPO 和在线 GRPO 已有训练代码，标准 PPO 没有。RL 门禁目前拒绝 UNKNOWN 数据；真实同 loader 零步对照、从同一 adapter 继续 SFT 的对照尚未实现，不能用 `preflight-only` 或仅传 `--sft-adapter` 冒充。

1. 从冻结的修复记录和来源组划分重建 entity train；只复用旧实体样例构造，不调用旧 relation 的 NONE 构造或证据 fallback。保存 train/tune group 无交集证明、文本和标签版本、原文定位覆盖。
2. 以 Qwen3-8B 新建干净实体 LoRA，训练3个完整epochs，逐epoch保存和评测完整tune。实体选模用 free_text entity micro F1，平手按recall、较早checkpoint；规则在训练前写进该阶段manifest。不能用 relation 的oracle指标挑实体模型。
3. 新入口从原始输入做 source routing→实体模型→grounding/ID→现代 relation `build_batches/render_prompt/parse_decisions/assemble_decisions`→规则→图。单卡可分两个进程顺序加载模型，但同一个run必须重算实体，不能沿用历史cache。
4. 新实体产物附 sample_index、原始输入SHA、模型/adapter/模板/代码hash。旧cache保持unverified；不能补一个新hash就把历史来源升级成已验证。
5. 回归覆盖空实体、漏实体、坏/重复ID、方向翻转、同对多关系、额外假边、缺行/乱序、输入hash错误、截断与ICD路由。无效输出不得被静默删除后抬高分数。

## P2—P3：足量训练和有限对照

正式SFT默认 seed42、BF16、LoRA r16/alpha32/dropout0.05、有效batch16、最大训练长度6144。学习率先沿用5e-5；只有P0证据显示不稳定才另登记有限学习率对照。正式预算为3个完整epochs，`max_steps=-1`，保存并完整评测epoch1/2/3，不能被旧的64步参数覆盖。当前1835行预计约345个optimizer steps，实际以trainer计数为准；新分批必须重新计算，不能硬编码345。

| ID | 只改变的因素 | 对照/预算 |
|---|---|---|
| S0 | 完整dense负例基线：full/hash/16 | P0仅用于诊断负例方案，S0重新从相同底座做完整训练 |
| S1 | 实体首次出现顺序source | 同S0原子监督清单、3次完整曝光；hash是固定输入驱动对照，不是标签排序 |
| S2 | 每次决策16→4对 | 同S0监督decision/正边/证据曝光；行数和更新数变化单列 |
| S3a/S3b | full_common与local_common | 相同目标与mask、3次完整曝光；分别记录全文监督被屏蔽的正例 |
| S4a/S4b | 审定/可证明候选范围上的dense与sparse | 同输入候选、正负信息和3次完整曝光；两臂固定10%可靠全负序列，未知银标不能造全负 |
| S5 | 在tune上选中的顺序/长度/协议组合 | 从底座完整重训；与S0完整全文监督基线比较，不能只胜过主动删监督的full_common |

10%的全负比例以正式发布后的行数计，配对dense/sparse必须一致；若要改成25%，先另登记对照，不能看测试结果后修改。sparse需同时实现版本化builder/prompt/parser/loss/evaluator：干扰实体保留在输入，答案只列有依据的正边；候选范围内的UNKNOWN不可因省略就被训练成负例。未审定普通语料仍走partial-mask合同；两种协议的数据范围、比例和剩余不确定性均报告。

顺序/分批重构前冻结带source group的原子decision、正边、证据和负例来源清单，重构后比较Counter而不只总数；覆盖差异不能隐去。训练曝光相同不等于GPU算力相同，输入/输出/监督token、updates、GPU秒分别报告。最终报告同时展示实际成本，不能把多训练的收益归因于短文本。

local选窗只读输入文本和预测实体，不读取gold关系或证据；用端点句窗并集，不能为漏掉的跨窗边凭空拼证据。训练中不可监督项按合同处理；评测中所有gold关系仍计入FN分母。统计长度、实体间距、跨句/跨窗、multi-disease、否定、单/多关系分层。测试ID改名、实体数组逆序、重叠mention及排序后图映射，排除位置捷径。

不穷举全部组合。S1/S2/S3/S4均需正式结果；只根据完整tune冻结一个S5，针对声称有效的关键因素做去项确认。组合若退化保留更好的单项或S0，不强行使用所有改动。

## P4：真实实体误差、规则和多关系

- 按train来源组三折训练实体模型，生成严格OOF候选；每条候选的生成模型不能见过该来源组。只有train预测进入relation适配和RL采样，tune/test实体预测不回灌训练。
- 同一选中关系配方比较gold候选训练与OOF候选适配，完整训练3epochs。实体缺失造成的关系不可达、grounding失败与relation误判分别归因。
- 每条规则在同一原始预测上独立评测删TP/删FP和FN变化；选定规则集只用tune。最终表同时列原始图与规则后图，不能只给precision提升。
- 多关系使用集合输出，报告每对标签集合exact match、label recall和支持数。历史只有30对，多关系样本不足时明确区间不稳定，不能把同对多关系降成单标签。

## P5：RL必须有正式比较，不能停在smoke

先完成同loader真实零步生成评测与显式继续SFT入口；验证继续训练前policy指纹等于选中SFT，reference冻结。GRPO零步覆盖SFT merge加零初始化残差LoRA。`--preflight-only`只检查数据，不能替代零步模型对照。

偏好只来自当前最佳SFT在train来源组的实际输出，以及有明确构造依据的完整小范围任务。目标512—1024对、尽量覆盖64个来源组；达不到则记真实数量，不能凑出假审定。保留chosen/rejected长度、边数差异、错误类别、原始输出hash、标签依据及审阅状态；增边/删边均需覆盖。银标未知不是错边，模型辅助审阅不能标成人工医学仲裁。没有语义审定的数据只允许使用机械可验证/构造范围，并明确泛化限制。

| 分支 | 有限筛选 | 正式预算与控制 |
|---|---|---|
| DPO | beta .05/.1、lr1e-6，至多64步，完整tune选择一次 | 选中beta在全部冻结偏好集训练2epochs；同起点0-step和继续SFT对照，最终seed17/42/73 |
| 在线GRPO | 先最长样例GPU与奖励验收，不据smoke报质量 | 预注册128 optimizer steps、G=4、batch1×gradient_accumulation16、beta .04、lr1e-6；32/64/128 checkpoints完整tune；最终seed17/42/73；实际rollout数以日志为准 |
| 奖励去项 | evidence权重.2对.0 | seed42同128步及同数据比较；不把短预算比较称单一奖励收益 |
| 标准PPO | 当前未实现 | 单列未执行；本轮在线RL由真实GRPO完成，不用名称混淆 |

每个正式RL分支都要完成全预算和完整评测；无收益也是正式结果。发现OOM或数值错误先修复数据/实现/内存使用，再登记新冻结run；不能静默缩预算、丢样本后称已完成。当前部分标注RL门禁保留：DPO先只允许完整审定或完整构造任务，修改reward不能让序列DPO损失自动兼容UNKNOWN；GRPO需完整审定范围或另行实现并验证partial-safe reward。禁止移除UNKNOWN字段绕过门禁。奖励测试覆盖全空/全连、漏正边、重复/非法边、截断、证据及答案长度作弊。DPO偏好accuracy不是抽取accuracy，beta不是实测KL；GRPO记录KL和各奖励分项。

继续SFT控制冻结相同起点、train来源组和chosen数据来源，预登记更新数及监督token/pair曝光，另列实测GPU时间；相同步数不能被称为等成本。三个RL seed分别接对应seed的最终SFT，保存父checkpoint/hash，不共用seed42起点后声称全训练链三seed。

主图指标用有向去重三元组，逐样本TP/FP/FN后全量汇总。实体漏检、窗口外、候选遗漏、全空、解析/截断失败造成的gold遗漏全部算FN；非法边算FP；缺行/身份错位视为整份评测未完成。free_text与ICD分表，oracle/fixed/live分表；原始严格gold与新仲裁gold另列，不能偷换分母。

Precision明确称精确率。开放图没有自然TN，不造Accuracy；仅在穷尽审定候选全集上报pair/label-set accuracy，披露UNKNOWN排除量及always-empty基线。每份报告保存原始预测并由独立脚本重算计数和F1。数值异常低时依次查身份/分母、生成解析、实体候选上限、拒绝分布、标签方向、证据标注，不能靠过滤困难样本修分。

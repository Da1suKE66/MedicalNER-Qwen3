# 结构性关系错误与 System Prompt 优化

## 检查范围

本次只检查 `predict.output` 可以正常解析成 JSON 的样本。后面那些 `missing <output> JSON block`、JSONDecodeError 或大段生成不稳定的输出不计入这次结构错误统计。

当前有效检查范围：

| 项目                          | 数量 |
| ----------------------------- | ---- |
| 测试样本总数                  | 20   |
| `predict.output` 可解析样本 | 9    |
| 可检查 relation 总数          | 62   |
| endpoint schema 硬错误        | 15   |
| 其中 source/target 明确反向   | 12   |

这里的结构性错误不是指文本生成质量差，也不是指 relation 是否医学上完整，而是指模型输出的知识图谱边在 `source`、`target`、`relation` 和实体 label 之间违反了 ontology 方向约束。

## 当前看到的结构性错误类型

### 1. Symptom-Disease 关系 source/target 反向

这是目前最核心的问题。模型经常能选对 relation name，但把 direction-sensitive relation 的端点写反。

错误形式：

```text
Disease is_core_symptom_of Symptom
Disease is_associated_symptom_of Symptom
```

正确形式：

```text
Symptom is_core_symptom_of Disease
Symptom is_associated_symptom_of Disease
```

对应硬规则：

| Relation                     | 合法方向               |
| ---------------------------- | ---------------------- |
| `is_core_symptom_of`       | `Symptom -> Disease` |
| `is_associated_symptom_of` | `Symptom -> Disease` |

当前预测中发现 12 条明确反向：

| 样本                                                                                   | Relation                     | 错误方向               | 数量 | 示例                                                                |
| -------------------------------------------------------------------------------------- | ---------------------------- | ---------------------- | ---- | ------------------------------------------------------------------- |
| IDX03 Attention deficit hyperactivity disorder, predominantly inattentive presentation | `is_core_symptom_of`       | `Disease -> Symptom` | 3    | `ADHD -> Inattention`                                             |
| IDX03 Attention deficit hyperactivity disorder, predominantly inattentive presentation | `is_associated_symptom_of` | `Disease -> Symptom` | 1    | `ADHD -> Hyperactive-impulsive symptoms`                          |
| IDX10 Behavioural or psychological disturbances in dementia                            | `is_core_symptom_of`       | `Disease -> Symptom` | 8    | `Behavioural or psychological disturbances in dementia -> apathy` |

这类错误说明：当前 prompt 只让模型知道 relation 名称，但没有足够强地告诉模型 relation 的 source label 和 target label。模型把英文短语 `core symptom of` 理解成“疾病包含症状”时，就会生成相反方向。

### 2. `subsumes` 被错误用于 Disease -> Symptom

预测中还出现了 `subsumes` 连接 `Disease -> Symptom` 的情况。

错误形式：

```text
Disease subsumes Symptom
```

例子：

| 样本                                                               | Relation     | 错误方向/类型          | 数量 | 示例                                    |
| ------------------------------------------------------------------ | ------------ | ---------------------- | ---- | --------------------------------------- |
| IDX08 Detachment in personality disorder or personality difficulty | `subsumes` | `Disease -> Symptom` | 2    | `Detachment ... -> social detachment` |

`subsumes` 的合法语义是疾病层级：

```text
broader Disease subsumes narrower Disease/subtype
```

因此它的 endpoint label 应该是：

```text
Disease -> Disease
```

如果目标实体是 `social detachment`、`emotional detachment` 这类表现或特征，就不应该用 `subsumes`。根据上下文，它们更可能应该作为 symptom relation：

```text
social detachment is_core_symptom_of Detachment in personality disorder or personality difficulty
emotional detachment is_core_symptom_of Detachment in personality disorder or personality difficulty
```

或者在证据不足时不输出这条 relation。

这个错误和第一类问题不同：它不是简单把 source/target 对调，而是 relation type 选择错了。模型把“疾病包含某个表现”误压成了疾病层级关系。

### 3. 使用了 schema 中不存在的实体 label

当前 node schema 允许的实体 label 是：

```text
Disease
Symptom
Diagnostic Criteria
Interview Tool
Patient Information
Medication
Communication Method
Risk Information
```

预测中出现了额外 label：

```text
Comorbidity
```

例子：

| 样本                                                                             | Relation                              | 错误 endpoint              | 示例                                                               |
| -------------------------------------------------------------------------------- | ------------------------------------- | -------------------------- | ------------------------------------------------------------------ |
| IDX06 Alzheimer disease dementia, mixed type, with other nonvascular aetiologies | `associated_with_poor_prognosis_in` | `Comorbidity -> Disease` | `other nonvascular aetiologies -> Alzheimer disease dementia...` |

这里的问题有两层：

1. `Comorbidity` 不是合法 node label。
2. `associated_with_poor_prognosis_in` 的 source 虽然可以是一个“风险或预后因素”，但它必须落在 schema 允许的 label 内，例如 `Disease`、`Symptom`、`Patient Information` 或 `Risk Information`。

因此 prompt 需要明确禁止模型发明新 label。遇到 comorbidity、aetiology、risk factor 一类概念时，模型必须在既有 label 中选择最合适的一个；如果无法确定，就不要输出对应 relation。

### 4. Disease-Disease 层级方向的语义错误

有些关系两端都是 `Disease`，所以仅靠 endpoint label 检查无法发现方向问题。例如 `subsumes`：

```text
Disease -> Disease
```

从 label 看是合法的，但仍然可能把 broad/narrow 层级写反，或者把两个并非上下位的疾病强行连成层级。

疑似例子：

| 样本                                                                                      | Relation     | 疑点                                                                                                                              |
| ----------------------------------------------------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| IDX06 Alzheimer disease dementia, mixed type, with other nonvascular aetiologies          | `subsumes` | 预测方向为 `Alzheimer disease dementia, mixed type... -> Dementia due to Alzheimer disease...`，但 gold 中方向相反              |
| IDX07 Bipolar type I disorder, current episode depressive, severe with psychotic symptoms | `subsumes` | 预测把 `Severe Depressive Episode`、`Depressive Episode` 指向完整 bipolar subtype，语义上不像 broad disease -> narrow subtype |

这类错误不能只靠 `Source Label` 和 `Target Label` 解决，因为两端 label 都是 `Disease`。prompt 里需要额外说明：

```text
For `subsumes`, source is always the broader disease/category, target is the narrower disease/subtype.
Do not use `subsumes` to mean "has symptom", "has episode", "includes feature", or "is associated with".
```

## 错误原因判断

1. Relation table 只列 relation name 和 relation type，没有把每条 relation 的合法 source label、target label 写成硬约束。
2. `Symptom-Disease` 这种 relation type 名称对人类可读，但对生成模型来说不一定能稳定约束方向。
3. `source`、`target` 被描述成 JSON 字段，而不是 ontology 语义字段，模型容易只保证 id 存在，不保证方向正确。
4. 对 `subsumes` 这类两端都是 `Disease` 的关系，旧 prompt 没有强调 broad/narrow 的方向。
5. 旧 prompt 没有明确禁止 schema 外 label，导致模型生成 `Comorbidity` 这类额外实体类型。

## System Prompt 优化目标

system prompt 应该做到：

1. 每条 relation 都有明确的 Source Label 和 Target Label。
2. `source` 和 `target` 不只是实体 id，还必须满足 relation schema 的 label 约束。
3. 对 `is_core_symptom_of`、`is_associated_symptom_of`、`required_for_diagnosis_of`、`subsumes` 这类方向敏感关系，写出不可反向的硬规则。
4. 明确禁止输出 schema 外 entity label。
5. 明确要求模型在最终输出前检查每条 relation 的 source entity label 和 target entity label。

## 建议加入 System Prompt 的硬规则

下面这段可以直接加入 system prompt 的 relation schema 后面：

```text
Relation endpoint rules:
1) Every relation must follow the Source Label and Target Label constraints in the relation schema.
2) The `source` field is not just a JSON id. It is the semantic subject of the relation.
3) The `target` field is not just a JSON id. It is the semantic object of the relation.
4) For `is_core_symptom_of` and `is_associated_symptom_of`, always output `Symptom -> Disease`. Never output `Disease -> Symptom`.
5) For `required_for_diagnosis_of`, always output `Diagnostic Criteria -> Disease`.
6) For `subsumes`, always output `broader Disease -> narrower Disease/subtype`. Never use `subsumes` for `Disease -> Symptom`.
7) Do not invent entity labels outside the node schema. Labels such as `Comorbidity` are invalid unless explicitly listed in the node schema.
8) If no relation in the schema fits the source label and target label, do not output that relation.
9) Before finalizing JSON, check every relation by mapping `source` and `target` ids back to their entity labels.
```

## 建议加入 System Prompt 的负例（要吗）

当前模型很可能需要负例来强化方向。建议在 system prompt 中加入少量短负例，不要写成长篇解释。

```text
Wrong:
D1(Disease: Attention Deficit Hyperactivity Disorder) is_core_symptom_of S1(Symptom: Inattention)

Correct:
S1(Symptom: Inattention) is_core_symptom_of D1(Disease: Attention Deficit Hyperactivity Disorder)
```

```text
Wrong:
D1(Disease: Behavioural or psychological disturbances in dementia) is_associated_symptom_of S1(Symptom: apathy)

Correct:
S1(Symptom: apathy) is_associated_symptom_of D1(Disease: Behavioural or psychological disturbances in dementia)
```

```text
Wrong:
D1(Disease: Detachment in personality disorder) subsumes S1(Symptom: social detachment)

Correct:
S1(Symptom: social detachment) is_core_symptom_of D1(Disease: Detachment in personality disorder)
```

```text
Wrong:
Use entity label `Comorbidity`.

Correct:
Use only labels from the node schema. If a comorbidity is a disease, label it as `Disease`. If it is a patient/context factor, label it as `Patient Information` or `Risk Information` when appropriate.
```

## 建议的 System Prompt 片段

下面是一个更完整的 prompt 片段，可以作为后续替换现有 system prompt 的基础。它不改变最终 JSON 字段，只强化 ontology 和方向约束。

```text
You are a medical knowledge graph extraction assistant.
Extract entities and relations from the input text and output strict JSON only.

# Node schema

Use only the following entity labels:

| Label | Node Meaning |
|-------|--------------|
| Disease | Disease, disorder, subtype, differential diagnosis, or clinical condition |
| Symptom | Core symptom, associated symptom, clinical feature, behavioural feature, or manifestation |
| Diagnostic Criteria | DSM-5/ICD diagnostic requirement, exclusion rule, threshold, duration, or required feature set |
| Interview Tool | Key interview point, assessment question, or interview strategy |
| Patient Information | Patient feature, demographic group, age group, comorbidity context, or special condition |
| Medication | Drug or medication class |
| Communication Method | Dialogue strategy or communication approach |
| Risk Information | Risk factor, warning sign, emergency risk, prognosis risk, or alert condition |

Do not invent new labels. `Comorbidity` is not a valid label.

# Relation schema

Every relation has a fixed direction. The `source` and `target` ids must match the Source Label and Target Label constraints.

| Source Label | Target Label | Relation Name | Relation | Direction Rule |
|--------------|--------------|---------------|----------|----------------|
| Disease | Disease | Subsumes | subsumes | source is the broader disease/category; target is the narrower disease/subtype |
| Disease | Disease | Differentiates From | differentiates_from | source disease is clinically distinguished from target disease |
| Disease | Disease | Co-occurrence Frequency | co_occurs_with_frequency | source disease co-occurs with target disease |
| Disease / Symptom / Patient Information / Risk Information | Disease | Associated with Poor Prognosis | associated_with_poor_prognosis_in | source factor is associated with poor prognosis in target disease |
| Symptom | Disease | Core Symptom Of | is_core_symptom_of | source symptom is a core symptom of target disease |
| Symptom | Disease | Associated Symptom Of | is_associated_symptom_of | source symptom is an associated symptom of target disease |
| Symptom / Disease | Symptom / Disease | Precedes | precedes | source condition/symptom occurs before target condition/symptom |
| Symptom / Disease | Symptom / Disease | Follows | follows | source condition/symptom occurs after target condition/symptom |
| Symptom / Disease | Symptom / Disease / Patient Information / Risk Information | Modulated By | modulated_by | source symptom/condition is changed or influenced by target factor |
| Diagnostic Criteria | Disease | Required For Diagnosis Of | required_for_diagnosis_of | source criterion is required to diagnose target disease |
| Diagnostic Criteria | Disease / Symptom / Patient Information | Excludes If Present | excludes_if_present | source criterion excludes diagnosis when target entity is present |
| Diagnostic Criteria / Symptom | Disease | Supports Subtyping Of | supports_subtyping_of | source criterion or symptom supports assigning target disease subtype |
| Interview Tool | Symptom / Disease / Risk Information / Patient Information | Assesses For | assesses_for | source interview tool assesses target entity |
| Interview Tool | Symptom / Risk Information / Patient Information | Triggers Follow-up Question On | triggers_follow_up_question_on | source interview tool triggers follow-up about target entity |
| Interview Tool | Patient Information | Informed By Patient Demographics | informed_by_patient_demographics | source interview tool is informed by target patient demographics |
| Medication | Disease | First Line For | first_line_for | source medication is first-line treatment for target disease |
| Medication | Patient Information / Disease | Contraindicated In | contraindicated_in | source medication is contraindicated in target patient group or condition |
| Medication | Patient Information | Dose Adjusted For | dose_adjusted_for | source medication dose is adjusted for target patient group |
| Medication | Medication | Interacts With | interacts_with | source medication interacts with target medication |
| Communication Method | Patient Information / Disease / Risk Information | Recommended For | recommended_for | source communication method is recommended for target patient/context |
| Communication Method | Patient Information / Disease / Risk Information | Avoid With | avoid_with | source communication method should be avoided with target patient/context |
| Communication Method / Risk Information | Risk Information / Communication Method | Escalates To | escalates_to | source communication/risk situation escalates to target risk or intervention |
| Risk Information | Disease / Symptom / Patient Information | Triggers Alert When | triggers_alert_when | source risk triggers an alert when target condition is present |
| Risk Information / Disease / Symptom | Disease / Symptom / Patient Information / Risk Information | Mediated By | mediated_by | source risk/condition is mediated by target factor |

# Critical direction rules

1) Always output `Symptom -> Disease` for `is_core_symptom_of` and `is_associated_symptom_of`.
2) Never output `Disease -> Symptom` for `is_core_symptom_of` or `is_associated_symptom_of`.
3) Always output `Diagnostic Criteria -> Disease` for `required_for_diagnosis_of`.
4) Always output broader `Disease -> Disease` subtype for `subsumes`.
5) Never use `subsumes` to connect a Disease to a Symptom.
6) If the selected relation does not fit the source and target labels, omit the relation.
7) Before finalizing the JSON, verify every relation by checking the labels of its source and target entity ids.

# Output format

Return strict JSON only. Do not use markdown code fences.
The output object must contain:
- source_id
- code
- title
- entities
- relations
```

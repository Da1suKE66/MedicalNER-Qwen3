# 关系模型已验证改进、现存问题与 DPO 修改报告

快照：2026-10-19 北京时间20:55。此次由主任务直接核对，未调用subagent。DPO24正式训练已完成，完整130条评测仍在运行；本报告不等待或预报该结果。

当前保留的关系模型为Qwen3-8B LoRA：rank16、alpha32、dropout0.05、LR1e-4、2epochs、batch1/accum8、250次更新；全部1000条关系窗口各训练两次，包含542条来源记录、316个来源组。模型输出有语义的实体类型/名称、关系标签、原文证据，由程序校验并生成JSON。最新标签加权候选尚未替换该模型。

主结论：短窗完整监督和学习率调整有明确验证集收益，排序收益小；标签加权基本持平，既有两版DPO没有提升。当前选定流水线关系Precision56.53%、Recall41.54%、F1 47.89%，未达到70–80%。

## 1. 关系模型已经做过的修改与证据

所有正式结果都完成130条验证，以下只列69条自由文本的规则后关系micro-F1；61条结构化确定性结果不混入模型成绩。分母固定573条gold关系，失败样本保留；关系比较包括首尾实体类型、名称、方向与标签，不给模糊匹配加分。验证集反复用于选优，结果不是独立盲测或多seed统计证明。

## 2. 当前问题与明确例子

**实体端点缺失是最大的漏召回来源，但不是全部问题。** 原组合335个FN中262个缺至少一端实体，占78.21%；另外73个两端齐全的FN中，41个标签不符、31个未输出该实体对关系、1个被规则删除。长完整诊断条件只命中3/53。固定当前实体表，只能覆盖311/573条gold关系，即使这些全部正确且零FP，乐观F1也只有70.36%；关系模型单独无法达到80%。

**关系SFT训练分布缺少真实预测实体表的情况。** 全1000个关系训练窗口均有关系目标，没有空目标窗口；实体表最少2个节点，均使用complete_source_entities。推理时会出现漏项、噪声或单节点。缺少“当前实体之间没有可支持关系时应结束输出”的训练，是直接观察到的数据缺口；它是否造成强行输出尚待对照验证。不能直接把未标注关系或未标注窗口当负例。

**标签与连接对象混淆仍突出。** 样例547中，带偶尔/可选含义的表现被从associated改成core，造成2TP丢失、2FP增加。样例249中，两个症状→疾病关系被替换为症状→诊断条件关系，也损失2TP并增加2FP。样例609则在两个实体都已给定的情况下把rules_out写成differentiates_from。它们不是JSON错误，也不是单靠允许同义词就能纠正的近似匹配问题。

**记录结构和证据长度仍未解决。** 样例773/779只剩一个实际实体时输出4字段definition记录，关系需要6字段；它们正常EOS结束，不是截断。样例248窗口1在6条不同关系里分别复制整段约2400字符证据，第7条达到4096token上限而截断。这些具体失败窗口对应最终文档图并未产生额外TP损失；不能把失败窗口数当作FP/FN数量。

**银标也有歧义与遗漏。** 否定范围、相邻子类证据、core/associated和本体层级需要审定。FP表示不匹配冻结银标，不表示每条都已证明为医学幻觉。没有修改验证gold来提高分数。

LoRA实际加载、参数更新、完整曝光和保存已核验；尚无rank对照，所以没有证据将瓶颈归因于rank16容量不足。格式与语义错误仍存在，不能把pipeline称为全部修好。

## 3. DPO到底修改了什么

**主要修改偏好数据及审核，沿用标准sigmoid DPO，没有提出或验证新DPO算法。** policy与冻结reference都从原选定关系SFT初始化；比较完整回答的条件log-probability，prompt不计损失，completion包含EOS。不是只训练被修改的标签，也没有把模型目标改成JSON或数字编号。

| 项目 | 旧版本 | 新DPO24的实际修改 |
|---|---|---|
| 样例组成 | DPO52为19个否定、17个方向、16个表外实体引用 | 13个正向肯定、8个明确否定、3个层级方向；本轮不含表外实体类 |
| 标签方向 | 否定类chosen为排除关系，rejected为核心症状，缺少相反方向的对应对比 | 补上chosen为核心症状、rejected为排除关系的13对，减少单向标签偏好 |
| 审查范围 | 重点审被改动的那一条；其它chosen银标不保证全部正确 | 先核对原文，再复核完整chosen；31个候选来源中保留24、隔离7 |
| 正负例构造 | 存在较容易的协议/表外引用负例 | 保留完整chosen共176条关系，每对只改变一条标签或方向，其它记录不变 |
| 外部模型作用 | 上轮主要本地审查 | 程序构造候选，DeepSeek Flash参与审查，62次成功调用覆盖31个既有TRAIN来源；并非生成31篇新文档 |
| API审核提示 | 对“刻意错误的负例”意图含糊，出现拒绝返回负例 | v2明确A/B是用于偏好学习的正确/故意错误候选，单独复审；保留旧失败记录 |

实际例子（仅解释被修改字段，完整回答的其它关系不变）：

- 原文明确支持必要特征：chosen=`症状 → is_core_symptom_of → 疾病`；rejected只改为`argues_against`。
- 原文明确否定某精确亚型伴随该症状：chosen=`症状 → argues_against → 该亚型`；rejected只改为`is_core_symptom_of`。限定亚型不能泛化到所有同类疾病。
- 原文明示子类包含关系：chosen=`子类 → subtype_of → 父类`；rejected交换首尾实体。

未标注保持未知，不构造NONE标签。7个隔离候选包括否定限定不完整、相邻子类证据、标签支持不足或API选择自相矛盾等，不把7个都认定为医学错误。这24对仍为经过审查的银标偏好，不是医学专家gold。

**新DPO仍有明确不足：** 24对很小，只有6次更新；尚未覆盖core与associated的主要混淆、rules_out与differentiates_from、症状应连疾病还是诊断条件、经审定的空关系输出等。当前负例是人工规则构造的局部错误，尚未证明能代表模型实际错误分布。完整chosen即便复核仍受银标质量限制，标准整段概率目标仍可能受长度/措辞影响。没有等量继续SFT及多seed对照，不能从DPO208/52/24之间的差异单独归因某一参数。DPO不能补回上游缺失实体，训练loss下降也不证明F1提升。

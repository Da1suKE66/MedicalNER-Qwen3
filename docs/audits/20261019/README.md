## 已完成基线结果

全部 130 条均计分；下表单列 69 条自由文本，原始分母为实体 648、关系 573。Precision 是精确率，不是包含真负例的 accuracy。oracle 使用正确实体，仅用于定位关系阶段问题，不是完整流水线成绩。

| 条件 | TP / FP / FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| live 实体，raw | 382 / 185 / 266 | 67.37% | 58.95% | 62.88% |
| live 实体，规则后 | 382 / 178 / 266 | 68.21% | 58.95% | 63.25% |
| live 关系，raw | 112 / 266 / 461 | 29.63% | 19.55% | 23.55% |
| live 关系，规则后 | 109 / 180 / 464 | 37.72% | 19.02% | 25.29% |
| oracle 关系，raw | 188 / 166 / 385 | 53.11% | 32.81% | 40.56% |
| oracle 关系，规则后 | 181 / 144 / 392 | 55.69% | 31.59% | 40.31% |

61 条结构化记录单列为确定性处理：实体 F1 80.00%、关系 F1 75.50%，不能用它代替自由文本模型效果。整体 130 条 live 规则后实体 F1 66.62%、关系 F1 32.77%。目前没有达到 70–80% 自由文本抽取目标。

实际 live 实体表仅覆盖 573 条 gold 关系中的 311 对端点，262 条关系至少缺一个正确端点；另有 202 条关系虽然两个端点都在表内，仍被漏掉。Diagnostic Criterion 实体只命中 6/83，不能仅看实体总 F1。live 有 23 次失败生成（135 次任务），其中 5 次达到输出预算；oracle 有 18 次失败（69 次任务），其中 8 次达到输出预算。输入没有被截断，也没有输入预算拒绝。最终 JSON 由程序组装，合法率 100% 不能证明语义记录或关系正确。

规则在 live 删除 86 个 FP，同时删除 3 个 TP；oracle 删除 22 个 FP，同时删除 7 个 TP。因此不能笼统断言规则总有提升。已做只读“失败输出逐行保留合法项”复盘：live 规则后 TP 增加 9，但 FP 增加 65，F1 从 25.2900% 变为 25.2137%，未启用该行为。所有评分都保留失败样本的全部 gold，没有模糊匹配加分。

## 短窗口实体对照：全量完成

保持同一个完整来源关系模型，替换为修复短窗口实体模型。两轮训练的 1361 行均访问两次，342 次更新；全部 130 条原始输入和 gold 完整评测，独立复算通过。以下仍只列 69 条自由文本：

| 条件 | TP / FP / FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| 短窗实体，raw | 379 / 141 / 269 | 72.88% | 58.49% | 64.90% |
| 短窗实体，规则后 | 379 / 138 / 269 | 73.31% | 58.49% | 65.06% |
| 短窗实体＋完整来源关系，raw | 120 / 175 / 453 | 40.68% | 20.94% | 27.65% |
| 短窗实体＋完整来源关系，规则后 | 119 / 164 / 454 | 42.05% | 20.77% | 27.80% |

相对完整来源实体，实体 F1 增加 1.82 个百分点、流水线关系 F1 增加 2.51 个百分点。但实体 TP 少 3、FP 少 40，属于精确率改善而召回略降；gold 关系的端点覆盖从 311/573 降为 294/573。Diagnostic Criterion 只从 6/83 提高到 10/83，长完整标准仍是弱项。125/125 个实体窗口均成功，无缺 EOS 或解析失败；关系阶段仍有 16 次语义记录失效和 4 次缺 EOS，不能声称全部输出问题已解决。

第二次独立复核重新解码了全部 125 个窗口的 token/EOS，确认最大实体输出为 565 tokens。83 条诊断标准均完整可见，其中超过 160 字的 53 条在两版中均为 0 个精确 TP；新增 4 个标准 TP 都不超过 80 字。来源 220、248 的密集疾病列表分别损失 23、22 个 gold 实体，所漏名称也都完整可见。因此不能把这些漏召回归因为切窗截断。端点覆盖新增 70 条、损失 87 条；关系 TP 新增 48 条、损失 38 条，其中一部分来自生成成功/失败变化，不能仅看净增 10 条。原有自由文本分层及全部 gold 保持不变。

按结果揭晓前声明的 `live.filtered.free_text.relation.f1` 标准，选短窗实体策略，随后两种修复关系视图均复用它的同一批真实 live 实体结果。缓存已逐窗口检查原始身份、提示、token/EOS 和解析状态；后续实际评测还会复查内存权重。两个关系视图都用 batch 8，先前完整来源关系用 batch 4，数值批处理条件也有差别；不能把相对完整来源的变化全归因于长度。原文顺序与语义名称顺序两项之间的实体结果、batch、监督曝光及训练参数保持配对。

## 短窗口来源顺序关系：全量完成

固定同一批真实短窗实体结果，新的关系模型已完成全部 130 条 live/oracle 评测，独立 TP/FP/FN 复算通过。实体图哈希与此前完全一致。以下是 69 条自由文本的关系指标，原有 573 个 gold 全部保留：

| 条件 | TP / FP / FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| live，规则前 | 178 / 267 / 395 | 40.00% | 31.06% | 34.97% |
| live，规则后 | 177 / 243 / 396 | 42.14% | 30.89% | 35.65% |
| oracle，规则前 | 269 / 185 / 304 | 59.25% | 46.95% | 52.39% |
| oracle，规则后 | 262 / 155 / 311 | 62.83% | 45.72% | 52.93% |

全部 130 条 live 规则后关系 F1 为 40.91%；结构化分层保持 75.50%，自由文本仍是难点。与此前相同实体、完整来源关系的 batch 4 结果相比，自由文本规则后 F1 增加 7.85 个百分点，TP 增加 58、FP 也增加 79，精确率几乎不变。后续完成的 batch 8 完整来源对照为 26.62%，同批量比较详见下节；监督曝光和更新数也有变化，不能把全部收益归因于缩短长度。

live 的 125 次关系生成全部有 EOS，最大输出 1461 tokens；15 个窗口仍因引用给定实体表以外的名称而失败（56 条非法记录），没有 JSON 或 TAB 语法错误。oracle 仍有 3 个缺 EOS 窗口和 12 个实体引用失败窗口。规则在 live 删除 24 个 FP 和 1 个 TP；oracle 删除 30 个 FP 和 7 个 TP。非法尝试附加 FP 的诊断 F1 单列保存，不能与上述纯图集合 F1 混用。

端点覆盖仍为 294/573：279 条 gold 缺少至少一个实际实体端点，另外 117 条在端点齐全时仍未命中。在固定这批实体、关系只能引用表内实体的条件下，即使全部 294 条可达关系都正确输出且没有 FP，自由文本关系 F1 也最多为 `2×294/(573+294) = 67.82%`。这是当前实体输出的条件上限，并非未来模型的上限；达到 70–80% 必须同时改善实体召回。完整聚合结果见 [relation-short-source-results.json](relation-short-source-results.json)。

第二次独立复核重新检查了全部 250 个关系窗口及 125 个实体缓存事件，最终图、token/EOS、原始 gold 分母均一致。规则后 live 的 396 个 FN 可分为：279 个缺实际端点、55 个同端点其他标签、9 个同标签反方向、53 个其他遗漏；这些是相对冻结银标的归因，不代表人工裁决的临床错误。涉及诊断标准端点的 107 条 gold 关系，live 只命中 10 条，oracle 命中 67 条。原文级错误解释留在本地私有报告，不公开医学原文。

针对该新模型，另用保存文本做了全 130 条离线逐行隔离复盘：原始预测及完整 live 指标首先精确重现，再尝试保留有 EOS 的失败输出中结构合法的行，仍执行原有证据过滤和跨窗口去重。规则后 TP/FP/FN 从 `177/243/396` 变为 `185/245/388`，诊断 F1 为 36.89%，增加 1.24 个百分点；8 个新增 TP 全部来自同一个来源。缺 EOS 输出没有被救回，失败标记未清除。这个结果尚未部署，也不是新增模型训练的成绩，不能替换主表的 35.65%。

## 短窗口语义排序关系：全量完成

与来源顺序实验相比，训练来源、窗口、完整监督曝光、初始化、学习率、两轮更新及评测条件保持配对，改变的是实体表与目标关系记录的排序。输出仍为实体类型、名称、关系标签与原文证据。实际实体图哈希完全一致，关系推理同为 batch 8。以下为 69 条自由文本的关系结果：

| 条件 | TP / FP / FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| live，规则前 | 177 / 233 / 396 | 43.17% | 30.89% | 36.01% |
| live，规则后 | 176 / 224 / 397 | 44.00% | 30.72% | 36.18% |
| oracle，规则前 | 326 / 182 / 247 | 64.17% | 56.89% | 60.31% |
| oracle，规则后 | 322 / 166 / 251 | 65.98% | 56.20% | 60.70% |

全部 130 条 live 规则后关系 F1 为 41.46%。相对来源顺序，自由文本 live 规则后 F1 只增加 0.53 个百分点：TP 少 1、FP 少 19，精确率有所提高，召回略降。oracle 则增加 60 个 TP、11 个 FP，F1 增加 7.77 个百分点，说明在本次正确实体条件下排序更有帮助；不能把 oracle 的 60.70% 当成真实流水线效果。

稳定性仍有问题。live 有 21 个语义记录失败窗口和 3 个缺 EOS 窗口，合计 24/125，来源顺序为 15/125。语义记录错误包括 35 条未知实体引用与 10 条七字段记录，而协议要求六字段；最终 JSON 仍由程序合法生成。oracle 有 13 个语义记录失败窗口和 3 个缺 EOS 窗口。额外惩罚非法尝试的 live `strict_raw` 诊断 F1 为 29.50%，低于来源顺序的 32.66%，因此没有稳定性改善的结论。输入没有截断或预算拒绝，达到 4096 的缺 EOS 输出保留为失败，所有 gold 仍计入 FN。

第二次独立复核通过全部图集合、125 条缓存事件、两版共 500 次关系生成的 token/EOS 及训练曝光检查。live 的 `is_associated_symptom_of` TP 从 57 增至 89，但 `is_core_symptom_of` 从 33 降至 10、`subtype_of` 从 16 降至 3。同端点标签错误导致的 FN 从 55 增至 65。反向预测对应的 FN 从 9 降至 3，也不表示学会了正确方向：消失的 6 个反向输出没有任何一个变成正确 TP，gold 仍然漏检。三个原文级案例已保存本地，分别展示七字段及重复输出、core/associated 混淆、跨窗口证据被规则删除正确关系。

实体仍固定为原有结果，279 条关系缺端点，另有 118 条端点齐全但漏检。同批量完整来源对照现已完成，按原先固定标准选中短窗语义排序。实体 LR 1e-4 已完成全量两轮训练：1361 行各访问两次、342 次更新、396202 个监督 tokens，除学习率及输出路径外的参数、初始权重、数据、实际曝光均与旧实体训练一致，保存权重核验通过。新旧实体评测使用同一选定关系模型，并分别配置相同的 entity batch 4 / relation batch 4；旧实体来自原 batch 4 真实生成缓存，两个关系结果均重新生成。旧实体对照已完成：自由文本规则后关系 TP/FP/FN 为 176/221/397，Precision 44.33%、Recall 30.72%、F1 36.29%；规则前 F1 36.20%。全部 130 条规则后关系 F1 为 41.57%。125 个关系窗口中 25 个失败（22 个语义记录失败、3 个缺 EOS），所有 gold 仍计分。新实体模型已核对实际 GPU 权重并开始完整评测，尚不能作学习率选优。训练与两组完整评测合计预留 7800 秒，另留 900 秒审核，后续学习率选择必须等待两组完整结果。关系学习率实验保留原固定实体条件；任何新实体与新关系的最终组合必须另行完整实测。详见 [后续参数计划](parameter-continuation-plan.json)。

## 同批量完整来源对照与关系方案选择

三个关系方案现在均完成全部 130 条的 live/oracle 评测并通过独立复算，使用相同的真实实体输出、runtime、evaluator、batch 8 和生成预算。以下主表只列 69 条自由文本、全部 573 条 gold 关系：

| 关系方案 | live TP / FP / FN，规则后 | live F1，规则前 | live F1，规则后 | oracle F1，规则后 |
|---|---:|---:|---:|---:|
| 完整来源 | 113 / 163 / 460 | 26.33% | 26.62% | 37.10% |
| 短窗来源顺序 | 177 / 243 / 396 | 34.97% | 35.65% | 52.93% |
| 短窗语义排序 | 176 / 224 / 397 | 36.01% | 36.18% | 60.70% |

完整来源在全部 130 条上的 live 规则后关系 F1 为 34.00%。自由文本 live 有 17 个语义记录失败和 4 个达到 4096 tokens 仍无 EOS 的窗口；oracle 分别为 10 和 9 个。所有失败和原有 gold 均保留，没有输入预算拒绝。JSON 由程序组装，仍不能据此声称语义输出全部合法。

同一实体和完整来源关系模型，旧 batch 4 的 live 规则后结果为 `119/164/454`、F1 27.80%，此次 batch 8 为 `113/163/460`、26.62%。实体图与提示不变，但部分贪心 completion 不同，因此新旧 batch 的分数不能混作学习率对照。已安排的新实体实验使用新旧双方一致的 batch 4，两个关系结果都重新生成。

按揭晓结果前冻结的 `live.filtered.free_text.relation.f1` 标准，选定短窗语义排序。相对完整来源，同批量主 F1 增加 9.56 个百分点；相对短窗来源顺序只高 0.53 个百分点，且失败更多，不能宣称排序稳定优于来源顺序。这仍是反复使用 tune 的单种子选择，不是盲测结果。缩短输入、补齐重叠监督、增加更新数的组合值得继续；其各自的独立贡献尚未分离。

## DPO 候选准备状态

已从冻结 train 来源准备 64 对结构遵循候选：48 对候选训练、16 对机械留出，接收来源与干扰名称来源在四个角色分区之间均无组交集。chosen 保留整条窗口的完整正例；rejected 只将一处端点名称替换为给定实体表和原文中不存在的同类型训练来源名称，其余正例不变。64 对完整 completion 的 token 长度逐对相等，未把未标注关系或 UNKNOWN 当负例，没有 `NONE`、数字选择或 JSON 训练目标。

这批候选只针对“引用表外实体”的协议错误，覆盖 Disease/Symptom，未覆盖长 Diagnostic Criterion；也不能训练出可靠的临床标签与方向判别。机械留出仍来自 SFT 的 train 来源，不是临床盲测集。候选尚未正式准入、未训练。对应语义 DPO 入口的私有 v1 草案通过 39 项 CPU/NumPy/tokenizer 检查，但独立审核发现最后核验前过早标记完成、核验跨截止时间后仍可成功两个问题。新 v2 已修复，53 项作者本地检查及 3 项新增独立检查均通过；真实 Torch、GPU、权重加载与保存重载尚未验证，没有部署到运行队列。仍须锁定对应语义 SFT reference 并完成全 130 条真实流水线评测，才可声称 DPO 有效。密钥和候选原文均未进入 GitHub，扩增样本正式准入数仍为零。

## 实体互补性的离线诊断

将已实测的全文与短窗实体输出按类型和规范名取并集，不使用 gold 选择保留项，自由文本实体得到 `467/241/181`，精确率 65.96%、召回率 72.07%、F1 68.88%。相对短窗增加 88 个 TP，同时增加 103 个 FP；主要补回 Disease/Symptom，长诊断标准仍是 0/53。这个并集尚未部署，后续实体学习率计划不变。

并集能够提供两端点的 gold 关系从 294 增至 381/573，但没有运行并集后的关系模型。假设这些关系全部正确且零误报，理想 F1 上限为 79.87%，这不是测得的关系成绩，也不代表达到目标。更大的实体表可能增加关系混淆和幻觉；若后续采用，必须明确两份来源的身份并重新做完整流水线评测，不能伪装成当前单一来源的实体缓存。

## 数据来源与隔离

冻结来源共 1345 条：train 1215 条，包含 670 条自由文本和 545 条结构化记录；tune 130 条，包含 69 条自由文本和 61 条结构化记录。来源组分别为 545 和 61，无跨拆分来源组交集。606 个组的标题全部来自同组结构化输入，保存原记录 SHA 与原 user 字符切片；标题不从 gold 规范名补造。

旧实体训练文件的 1563 行中有 119 行来自当前 tune 的 69 条来源；旧关系训练文件的 1135 行中有 89 行来自当前 tune 的 49 条来源。本轮从冻结 train 来源重建，没有复用这两份训练文件。备用 858 来源拆分与当前拆分不能直接拼接，其训练部分也覆盖当前 tune 与历史评测来源，必须按当前来源身份重新隔离。

模型训练使用自由文本。结构化记录完整处理并单列确定性基线，避免大量简单结构样本掩盖自由文本结果。670 条自由文本全部经过编译审计，其中 2 条原有隔离来源不进入监督，得到 668 个实体训练来源和 542 个关系训练来源。

实体原有 6516 条标注，扣除隔离来源的 17 条、无来源支持规范名 9 条、精确 mention 不可用 4 条，并合并 2 个重复类型/规范名 ID，准入 6484 条。关系原有 5592 条标注，扣除隔离来源的 15 条、端点不可用 22 条、原有 pair 阻断 2 条和目标类型冲突 2 条，准入 5551 个证据监督原子。跳过项不是负例。

## 短窗实体监督修复

源文本划窗应产生 1361 个有效来源窗口，旧实体文件只保存 1092 行。269 个含有已准入实体的窗口没有训练，另一些窗口只保存部分可见实体；合计漏掉 2199 次“窗口内可见的已准入实体”监督。新版 `short_source_complete_windows` 保留原有 6484 个文档实体身份，在每个窗口加入全部能在该窗口正文或已验证标题中定位的原标签，得到 1361 行、8683 次实体窗口监督。没有新增医学断言，没有把未知空窗口当负例。

训练和推理使用相同的来源划窗、2400 字符预算、400 字符重叠和字面提示；独立复核逐一比较了全部 1361 个提示。推理显式指定 `--entity-variant short_source`，成功窗口的实体按类型和规范名合并；正文位置还原到原文，标题保留来源凭据。失败窗口不补造结果，部分结果标记不完整，全部原始 gold 仍进入计分。

新实体 arm 仍从相同 base 训练，LR 5e-5、rank 16、2 轮，已完成 342 次更新，每个窗口访问两次，保存权重逐位核验通过；配同一个完整来源关系 adapter 的全部 130 条评测也已完成。它同时改变输入长度、重复监督和更新数，不能作为纯长度消融。后续关系方向比较固定该短窗实体策略。

完整来源基线出现 3 个实体生成重复案例，分别达到 4096 token 上限；其正常 gold 输出仅为 440、667、285 tokens。训练目标内没有重复实体行，EOS 也确实参与监督，因此目前不能把原因直接归为输出预算太小或缺少 EOS。上述旧短窗问题位于尚未使用的训练文件，不能解释完整来源基线的重复。

## 关系重叠监督修复与配对

按原证据选定的位置核验，旧关系短窗遗漏 308 次“同一证据在另一来源窗口内完整出现”的监督，涉及 143 个来源、175 个窗口；其中 49 个含有正例的窗口整行缺失。另有 82 个同文证据在不同位置出现的情况，因作用范围不能确认，没有迁移标注。3 个证据原子跨越所有短窗，保留原有 2 行完整来源辅助训练；推理不按 gold 选择回退窗口。

新版 `relation_complete_overlap_v2` 从服务器已有的完整来源和目标重建，逐一验证全部 5551 个原证据位置与本地审核一致，只部署代码和聚合哈希参数。来源顺序与语义名称顺序两种视图均为 1000 行、5551 个不同证据原子、5859 次证据监督、1000 个 EOS，每轮 125 次更新。每行窗口、监督原子及 token 预算配对，输出仍是语义名称和关系标签，没有变回数字编号。

两个关系 arm 均使用 LR 5e-5、rank 16、2 个完整 epoch，并均已完成 250 次更新。两版各 1000 行均访问两次（2000 次 microstep、799946 个监督 tokens），保存权重逐位核验通过，各耗时约 28.9 分钟；非数据参数、初始 adapter、token 总量和实际曝光相同。两版全 130 条 live/oracle 评测均已完成，结果见上表；使用实体实验中选出的同一模型、输入策略及真实实体结果。新增重叠监督同时改变曝光与更新数，相对完整来源的差异不是纯长度效应；两种修复短窗之间的比较才用于分析顺序变化。

为排除批量条件混杂，已完成同一完整来源关系 adapter 的 batch 8、当前 runtime 对照，也覆盖全部 130 条 live/oracle 并复用同一批真实实体结果。三个关系方案的实体、batch、输出预算和 runtime 一致；完整来源与短窗的监督曝光和更新数差异仍需披露。独立复算后按自由文本 live 规则后关系 F1 选定短窗语义排序；平局规则及全量要求见 [关系比较计划](relation-comparison-plan.json)。此计划在查看任何修复短窗关系完整结果前记录，旧 batch 4 分数保留。

## 监督与标签覆盖限制

训练目标是语义 TAB 行，由程序组装 JSON。prompt 和 padding 标签为 `-100`，完整 completion 编码一次并附加一个 EOS。EOS 表示所提供标注序列结束，不证明未标注关系均为负类。没有把 UNKNOWN 转成 `NONE`、空银标监督或 DPO 负例。

实体中 Symptom、Disease、Diagnostic Criterion 合计 6377/6484，约 98.35%；Assessment、Medication、Examination、Assessment Scale 分别只有 1、2、3、4 条。27 种训练关系中前 5 种占 4436/5551，约 79.91%，8 种关系不超过 9 条。训练关系中未出现的 `suggests` 在 tune 有 2 条；这是覆盖缺口，不能据此从 tune 造训练样例。

原 train 自由文本中 124/670 条没有关系标注，tune 中为 18/69 条。由于银标不完整，这些来源不自动视作可靠“无关系”任务，因此当前关系 SFT 目标全部非空。模型可能仍有偏向输出关系的风险，需以完整评测验证。后续扩增应从允许的训练来源出发，按预先确定的标签覆盖计划补充有明确证据的少数类、方向/限定词对照和经审核的无关系任务；不要大量复制单例银标或把未标注 pair 当可靠负例。

## 评测与训练代码核验

tune 的 130 条原始记录与全部 gold 保留：自由文本 648 个实体、573 条关系，结构化部分单独分层。只有 572 个自由文本关系证据原子可用于同协议的监督编译，缺少定位的 1 条仍留在评测分母。历史 148 条属于已经查看过的回归集，不作为新的盲测集；标题增强必须另有原始来源映射证据。

正式质量指标使用实际实体输出进入关系阶段后的 `live.filtered.free_text.relation`：按类型、规范名、方向及关系标签严格比较去重集合，报告 TP、FP、FN、precision、recall 和 F1。对应 `live.raw` 的纯集合指标必须同时列出，以观察规则删除了多少正确与错误关系。`strict_raw` 额外把无效输出行计入 FP，是无效输出惩罚诊断，不与纯集合 F1 混称。旧评测快照若将该诊断字段列为 `primary_metric`，解读时仍以原始 `filtered`/`raw` 集合字段为准，不重算或修改任何分子、分母。

历史评测发布保留全部 148 条、979 个实体和 704 条关系。81 条自由文本中，57 条通过原文精确匹配及同源结构化记录验证标题，24 条无法验证标题的样本保留原文与全部 gold，不猜标题、不移除样本。其标题输入条件与过去实验不同，不能把分数差异全部归为模型提升。

训练入口逐行拒绝 tune、混合 stage 和重复身份；正式运行还必须提供审核发布清单中的数据 SHA。记录实际完成的 microstep 与每行曝光；正式完成要求每行至少达到整数 epoch 次数。LoRA 初末指纹必须变化，保存后的 safetensors 与内存参数逐项逐位比较。异常处理清除 `completed` 并标记失败，runtime 拒绝失败或 smoke adapter。

对安装的 Transformers 4.56.2 源码核对显示，Qwen3 的 loss 使用累计 microbatch 中非掩码目标 token 总数作分母，`ObservedTrainer` 没有再次除以梯度累计数。低 token 平均 loss 不能替代实体/关系精确率或 F1。代码核验与数据长度核验均不构成训练质量结论。

后续关系比较可显式开启 `--entity-cache-run`，复用同一个已完成评测的真实 live 实体输出，固定实体条件并节省重复推理。默认关闭；要求原运行完整覆盖 130 条、runtime/protocol/输入/实体 adapter 哈希一致，逐窗口重建提示，重新验证 token、EOS、解析状态与内存权重。缺 EOS 或失败窗口原样失败，不以 gold 补齐。缓存不能链式复用，不允许旧 runtime 白名单；关系仍调用模型。 首次真实关系评测已通过缓存 token/EOS 和实际加载 GPU 权重核验，复用了 125 个实体窗口、没有新增 GPU 实体推理；完成后仍须核对全部实体图哈希和最终计分。计数 `new_gpu_relation_calls` 的单位是委托给 backend 的关系任务，包含拒绝或异常，不代表成功 GPU 解码。真实 130 输入与 Qwen tokenizer 的 CPU 接线复验通过，不能当成模型效果实验。

复现数据发布使用 `PYTHONPATH=agent python -m semantic.data --source-root <私有 repaired_v2> --output-dir <新目录> --tokenizer <本地 Qwen3 tokenizer> --max-length 8192`。发布器拒绝覆盖现有目录；完整私有输入用于重验来源切片与标注守恒。不要将派生窗口行数相加当成独立文档数量。

## 已完成基线结果

全部 130 条均计分；下表单列 69 条自由文本，原始分母为实体 648、关系 573。Precision 是精确率，不是包含真负例的 accuracy。oracle 使用正确实体，仅用于定位关系阶段问题，不是完整流水线成绩。

| 条件 | TP / FP / FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| live 实体，raw | 382 / 185 / 266 | 67.37% | 58.95% | 62.88% |
| live 实体，规则后 | 382 / 178 / 266 | 68.21% | 58.95% | 63.25% |
| live 关系，raw | 112 / 266 / 461 | 29.63% | 19.55% | 23.55% |
| live 关系，规则后 | 109 / 180 / 464 | 37.72% | 19.02% | 25.29% |
| oracle 关系，raw | 188 / 166 / 385 | 53.11% | 32.81% | 40.56% |
| oracle 关系，规则后 | 181 / 144 / 392 | 55.69% | 31.59% | 40.31% |

61 条结构化记录单列为确定性处理：实体 F1 80.00%、关系 F1 75.50%，不能用它代替自由文本模型效果。整体 130 条 live 规则后实体 F1 66.62%、关系 F1 32.77%。目前没有达到 70–80% 自由文本抽取目标。

实际 live 实体表仅覆盖 573 条 gold 关系中的 311 对端点，262 条关系至少缺一个正确端点；另有 202 条关系虽然两个端点都在表内，仍被漏掉。Diagnostic Criterion 实体只命中 6/83，不能仅看实体总 F1。live 有 23 次失败生成（135 次任务），其中 5 次达到输出预算；oracle 有 18 次失败（69 次任务），其中 8 次达到输出预算。输入没有被截断，也没有输入预算拒绝。最终 JSON 由程序组装，合法率 100% 不能证明语义记录或关系正确。

规则在 live 删除 86 个 FP，同时删除 3 个 TP；oracle 删除 22 个 FP，同时删除 7 个 TP。因此不能笼统断言规则总有提升。已做只读“失败输出逐行保留合法项”复盘：live 规则后 TP 增加 9，但 FP 增加 65，F1 从 25.2900% 变为 25.2137%，未启用该行为。所有评分都保留失败样本的全部 gold，没有模糊匹配加分。

## 数据来源与隔离

冻结来源共 1345 条：train 1215 条，包含 670 条自由文本和 545 条结构化记录；tune 130 条，包含 69 条自由文本和 61 条结构化记录。来源组分别为 545 和 61，无跨拆分来源组交集。606 个组的标题全部来自同组结构化输入，保存原记录 SHA 与原 user 字符切片；标题不从 gold 规范名补造。

旧实体训练文件的 1563 行中有 119 行来自当前 tune 的 69 条来源；旧关系训练文件的 1135 行中有 89 行来自当前 tune 的 49 条来源。本轮从冻结 train 来源重建，没有复用这两份训练文件。备用 858 来源拆分与当前拆分不能直接拼接，其训练部分也覆盖当前 tune 与历史评测来源，必须按当前来源身份重新隔离。

模型训练使用自由文本。结构化记录完整处理并单列确定性基线，避免大量简单结构样本掩盖自由文本结果。670 条自由文本全部经过编译审计，其中 2 条原有隔离来源不进入监督，得到 668 个实体训练来源和 542 个关系训练来源。

## 短窗实体监督修复

源文本划窗应产生 1361 个有效来源窗口，旧实体文件只保存 1092 行。269 个含有已准入实体的窗口没有训练，另一些窗口只保存部分可见实体；合计漏掉 2199 次“窗口内可见的已准入实体”监督。新版 `short_source_complete_windows` 保留原有 6484 个文档实体身份，在每个窗口加入全部能在该窗口正文或已验证标题中定位的原标签，得到 1361 行、8683 次实体窗口监督。没有新增医学断言，没有把未知空窗口当负例。

训练和推理使用相同的来源划窗、2400 字符预算、400 字符重叠和字面提示；独立复核逐一比较了全部 1361 个提示。推理显式指定 `--entity-variant short_source`，成功窗口的实体按类型和规范名合并；正文位置还原到原文，标题保留来源凭据。失败窗口不补造结果，部分结果标记不完整，全部原始 gold 仍进入计分。

新实体 arm 仍从相同 base 训练，LR 5e-5、rank 16、2 轮，已完成 342 次更新，每个窗口访问两次，保存权重逐位核验通过；配同一个完整来源关系 adapter 的全部 130 条评测也已完成。它同时改变输入长度、重复监督和更新数，不能作为纯长度消融。后续关系方向比较固定该短窗实体策略。

完整来源基线出现 3 个实体生成重复案例，分别达到 4096 token 上限；其正常 gold 输出仅为 440、667、285 tokens。训练目标内没有重复实体行，EOS 也确实参与监督，因此目前不能把原因直接归为输出预算太小或缺少 EOS。上述旧短窗问题位于尚未使用的训练文件，不能解释完整来源基线的重复。

## 关系重叠监督修复与配对

按原证据选定的位置核验，旧关系短窗遗漏 308 次“同一证据在另一来源窗口内完整出现”的监督，涉及 143 个来源、175 个窗口；其中 49 个含有正例的窗口整行缺失。另有 82 个同文证据在不同位置出现的情况，因作用范围不能确认，没有迁移标注。3 个证据原子跨越所有短窗，保留原有 2 行完整来源辅助训练；推理不按 gold 选择回退窗口。

新版 `relation_complete_overlap_v2` 从服务器已有的完整来源和目标重建，逐一验证全部 5551 个原证据位置与本地审核一致，只部署代码和聚合哈希参数。来源顺序与语义名称顺序两种视图均为 1000 行、5551 个不同证据原子、5859 次证据监督、1000 个 EOS，每轮 125 次更新。每行窗口、监督原子及 token 预算配对，输出仍是语义名称和关系标签，没有变回数字编号。

两个关系 arm 已加入持久队列，均使用 LR 5e-5、rank 16、2 个完整 epoch，预计各 250 次更新。关系评测会固定实体实验中选出的同一模型和输入策略，覆盖全部 130 条及 live/oracle 两种模式。新增重叠监督同时改变曝光与更新数，相对完整来源的差异不是纯长度效应；两种修复短窗之间的比较才用于分析顺序变化。

## 监督与标签覆盖限制

训练目标是语义 TAB 行，由程序组装 JSON。prompt 和 padding 标签为 `-100`，完整 completion 编码一次并附加一个 EOS。EOS 表示所提供标注序列结束，不证明未标注关系均为负类。没有把 UNKNOWN 转成 `NONE`、空银标监督或 DPO 负例。

实体中 Symptom、Disease、Diagnostic Criterion 合计 6377/6484，约 98.35%；Assessment、Medication、Examination、Assessment Scale 分别只有 1、2、3、4 条。27 种训练关系中前 5 种占 4436/5551，约 79.91%，8 种关系不超过 9 条。训练关系中未出现的 `suggests` 在 tune 有 2 条；这是覆盖缺口，不能据此从 tune 造训练样例。

原 train 自由文本中 124/670 条没有关系标注，tune 中为 18/69 条。由于银标不完整，这些来源不自动视作可靠“无关系”任务，因此当前关系 SFT 目标全部非空。模型可能仍有偏向输出关系的风险，需以完整评测验证。后续扩增应从允许的训练来源出发，按预先确定的标签覆盖计划补充有明确证据的少数类、方向/限定词对照和经审核的无关系任务；不要大量复制单例银标或把未标注 pair 当可靠负例。

## 评测与训练代码核验

tune 的 130 条原始记录与全部 gold 保留：自由文本 648 个实体、573 条关系，结构化部分单独分层。只有 572 个自由文本关系证据原子可用于同协议的监督编译，缺少定位的 1 条仍留在评测分母。历史 148 条属于已经查看过的回归集，不作为新的盲测集；标题增强必须另有原始来源映射证据。

正式质量指标使用实际实体输出进入关系阶段后的 `live.filtered.free_text.relation`：按类型、规范名、方向及关系标签严格比较去重集合，报告 TP、FP、FN、precision、recall 和 F1。对应 `live.raw` 的纯集合指标必须同时列出，以观察规则删除了多少正确与错误关系。`strict_raw` 额外把无效输出行计入 FP，是无效输出惩罚诊断，不与纯集合 F1 混称。旧评测快照若将该诊断字段列为 `primary_metric`，解读时仍以原始 `filtered`/`raw` 集合字段为准，不重算或修改任何分子、分母。

历史评测发布保留全部 148 条、979 个实体和 704 条关系。81 条自由文本中，57 条通过原文精确匹配及同源结构化记录验证标题，24 条无法验证标题的样本保留原文与全部 gold，不猜标题、不移除样本。其标题输入条件与过去实验不同，不能把分数差异全部归为模型提升。

训练入口逐行拒绝 tune、混合 stage 和重复身份；正式运行还必须提供审核发布清单中的数据 SHA。记录实际完成的 microstep 与每行曝光；正式完成要求每行至少达到整数 epoch 次数。LoRA 初末指纹必须变化，保存后的 safetensors 与内存参数逐项逐位比较。异常处理清除 `completed` 并标记失败，runtime 拒绝失败或 smoke adapter。

对安装的 Transformers 4.56.2 源码核对显示，Qwen3 的 loss 使用累计 microbatch 中非掩码目标 token 总数作分母，`ObservedTrainer` 没有再次除以梯度累计数。低 token 平均 loss 不能替代实体/关系精确率或 F1。代码核验与数据长度核验均不构成训练质量结论。

后续关系比较可显式开启 `--entity-cache-run`，复用同一个已完成评测的真实 live 实体输出，固定实体条件并节省重复推理。默认关闭；要求原运行完整覆盖 130 条、runtime/protocol/输入/实体 adapter 哈希一致，逐窗口重建提示，重新验证 token、EOS、解析状态与内存权重。缺 EOS 或失败窗口原样失败，不以 gold 补齐。缓存不能链式复用，不允许旧 runtime 白名单；关系仍调用模型。计数 `new_gpu_relation_calls` 的单位是委托给 backend 的关系任务，包含拒绝或异常，不代表成功 GPU 解码。真实 130 输入与 Qwen tokenizer 的 CPU 接线复验通过，不能当成模型效果实验。

复现数据发布使用 `PYTHONPATH=agent python -m semantic.data --source-root <私有 repaired_v2> --output-dir <新目录> --tokenizer <本地 Qwen3 tokenizer> --max-length 8192`。发布器拒绝覆盖现有目录；完整私有输入用于重验来源切片与标注守恒。不要将派生窗口行数相加当成独立文档数量。

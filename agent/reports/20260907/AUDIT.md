# Agent 审核、归因与改进计划

审核日期：2026-09-07。历史 agent 基线提交：`20ccab3`（与原本地 `75e660c` 的代码树完全相同）。新实验结果另见同目录 `RESULTS.md`；没有把新实验覆盖到旧模型。

## 1. 实际架构及本次改动

原有：结构化 ICD → Python 解析；自由文本 → Qwen3-8B/entity LoRA → 实体 grounding、去重、编号 → Qwen3-8B/relation LoRA 自回归生成 pair/relation/evidence JSON → 校验 → Python 组装。

本次保留路由、实体模型、归一化、校验和组装。只针对长期出问题的 relation 决策模块，增加可选的 **Qwen3-8B + LoRA 多标签分类头**：每个有序实体对读“实体名称、类型、局部原文”，一次前向计算关系分数，不生成编号、关系 JSON 或推理文字。允许同一实体对同时存在多种关系；全部低于阈值就是 NONE。编号与证据原文仍由程序绑定。

这不是增加一串新 agent，也不是已经证明小模型更好。仍使用现有 8B 底座，以避免同时更换底座引入额外变量。原来双 LoRA 可以共享一个因果语言模型；新的分类头与实体生成头不同，当前实现分别加载，80GB A100 可以承载，不能把它宣传成显存更省的小分类器。

## 2. 审核范围与版本脱节

- 检查了远程实际运行的 source/router、span、normalize、prompt、候选对、训练转换、SFT loss、推理异常处理、validator、assembler、评测及历史输出。
- 同时检查了仓库中的 `src/kg_lora/` 数据审计/清洗流程、训练配置与 schema。仓库已有更严格的数据门禁，但远程 agent 使用另外的转换链，不能把那些旧报告的“通过”当成这次训练的数据质量保证。
- 原始教师输出使用 `medical-kg-extraction-v3.1.1` 的模块式关系约定；仓库另有 schema v2/v3 草案。没有擅自将这些不同协议混用。新 `ontology.json` 从实际训练输入的 system schema 抽取，并明确其来源。
- 远程原端口仍可连接，本次无需换机器、扫描其他主机或覆盖旧工程。全部训练在独立实验目录进行。

## 3. 已证实的问题

| 环节 | 可复核证据 | 影响与处理 |
|---|---|---|
| 正负样本顺序 | v4 的 920 个正负混合 batch 全部“正例在前、NONE 在后”；v6 才改了顺序 | 存在位置标签捷径。新模型每对独立分类，输入不含 pair ID；有编号置换回归测试 |
| 训练/推理输入不同 | 6,165 条自由文本训练关系中，2,485 条在旧转换器中需要按 gold evidence 所在 chunk 注入端点 | 训练拿到推理时不存在的候选实体。新训练和推理共用纯输入驱动的候选/上下文函数 |
| 错误证据 | 911 条关系没有匹配证据、也没有同句双端点，却回退到第一句 | 教会模型把无关证据当正确答案。新路径无首句回退；无法核实的已标注 pair 为 UNKNOWN，不当 NONE |
| 实体对齐 | 910 条训练关系因端点无法对齐被丢弃 | 关系召回先受到实体覆盖限制。修复缩写/小数切句，保留所有明确 mention；缺失仍必须计入端到端 FN |
| Schema 不一致 | 13 条训练关系被额外手写 target-type 限制排除；实体标签表也与教师 schema 不一致 | 按实际 schema 统一合法标签空间；没有凭空补目标类型规则 |
| 多关系覆盖 | 31 个 endpoint pair 有重复标注，其中 30 个有不同关系类型；旧 dict 只保留最后一条 | 新标签为集合、使用独立 sigmoid；不是 softmax 单选。过滤后训练集仍仅有 2 个多标签 pair，能力远未充分训练 |
| 分句 | 17,268 个旧训练 span 中有 1,846 个单字符 span，包含被拆开的 e.g./i.e./小数 | 修复切句并测试原始字符偏移；长文本不等于需要更大的输出上限 |
| 长度 | 旧 v4 relation 仅 4/1,135 条训练序列超过 4096 tokens；v6 无超过 | 训练左截断确有问题，但不是主要数量级解释。超长不再静默删除 prompt |
| 推理截断 | 81 条自由文本中 39 条出现 relation 解析错误，共 111 次；最终组装 JSON 仍全部合法 | 最终 JSON closure 掩盖模型失败。新 scorer 单独报告阶段失败；分类头没有自回归输出截断 |
| loss | 旧 loss 是 completion token CE，JSON 模板、ID、NONE 都参与；没有关系验证指标 | 低 loss 不等于绑定正确。改为合法关系标签上的 BCE；用独立 tuning 集 P/R/F1/F0.5 选模型 |
| 评测 | 无效图跳过、无效端点边忽略、空预测 precision=1、三元组 F1 不含证据 | 修复失败计数和空集口径；补上分支、每类及同边证据指标 |

这些是代码/数据事实，不等于已经通过逐项消融确定每个问题的因果贡献。本轮是组合修复试验，不能把全部增益归功于分类器单一因素。

## 4. 训练数据到底是什么

实际输入是 `deepseek_watermark_20260804_182312_output_only_full_groupdisjoint_train.json`：1,345 条记录，其中 606 条结构化 ICD、739 条医学自由文本。标注是 **DeepSeek 教师生成的银标**，不是人工逐边审定的金标。ICD 不进入神经关系训练。

原始 train/dev 按来源组切分：606/67 个来源组，记录数 1345/148。上游索引保留源顺序；训练与历史 dev 的规范化原文完全重复数为 0。训练内部再固定抽取 61 个来源组做 tuning，其余 545 组训练。不同文本仍可能医学内容接近；没有把“无逐字重叠”说成无任何语义泄漏。

| 新数据 | 自由文本记录 | 有标签 pair | NONE pair | 全部 pair |
|---|---:|---:|---:|---:|
| Train | 670 | 3,051 | 7,195 | 10,246 |
| Tune | 69 | 383 | 5,331 | 5,714 |
| Dev oracle（仅诊断） | 81 | 408 | 5,884 | 6,292 |

训练正关系决策有 3,053 个，少于原始 5,592 条：端点、局部上下文或证据不能覆盖的条目未用于监督。另有 383 个候选对因已标注但证据/协议不确定而排除，不能拿它们充负例。训练对负例做约 1:2 采样并优先同文档相似端点；tuning/eval 不做相同负例下采样。

新输入示意（合成例子，不是实验结果）：

```text
SOURCE (Symptom): fatigue
TARGET (Disease): Condition A
SOURCE TEXT:
Fatigue is a core symptom of Condition A and supports diagnosis of Condition A.
```

监督标签为 `is_core_symptom_of` 与 `supports_diagnosis_of`。输入是名称和原文，**不是只给 S1/D1 猜意义**。旧 prompt 也包含实体名称；旧错误不能归因于“只输入代号”。

仍有数据限制：银标不一定穷尽所有关系，未标注 pair 不一定是真 NONE；尾部关系非常稀少，26 个训练标签中有的只有 1–3 例。Tune 有 2 条 `suggests`、dev oracle 有 1 条 `recommended_for` 未在训练标签中出现，必须保留为 FN。多关系样本太少，分类头支持多标签不等于已解决多关系问题。

## 5. 对那个 16000-token 样例的归因

重新逐边核对 sample_index=2：**TP=0、FP=32、FN=12**。此前“TP=1”来自三条样本合计，不能套到这个样例；三条共预测 33 条，不是 32 条。

- 12 条把同一列举中的行为症状互连成 `has_manifestation`；“并列列举”被误作“父项—表现”。
- 20 条将同一症状、同一句证据绑定到其他疾病。证据讨论 Disorders of Intellectual Development，目标却是 Autism/ADHD/Depressive/Bipolar 等。
- 4096 与 16000 的三个样例输出相同。加 token 消除了 JSON 截断，但不能修正这些语义绑定错误。没有做过“16000 tokens 的 148 条全量评测”，不能声称做过。

窄规则能移除这 32 条错误边，但这个样例已用于设计规则，属于已知回归修复；不是独立证明规则泛化。全量 81 条自由文本旧结果仅删掉 2 条 FP、0 条 TP，仍 TP=6、FN=632，几乎不改善 F1。规则默认可选，不以“证据没有字面出现目标名”一刀切过滤指代关系。

## 6. 训练、评测及保留标准

1. 固定 entity v4 缓存，比较旧 relation、旧 relation+规则、新分类器、新分类器+规则。主要看 81 条自由文本；67 条 ICD 单列，防止它掩盖神经分支的问题。
2. 本轮 Qwen3-8B，LoRA r=8/alpha=16/dropout=.05，lr=5e-5，2 epochs，batch=4、梯度累积=4、max input=768、positive weight=2、seed=42。保存每 epoch tuning 指标和 10 个阈值的扫点，不拿训练 loss 选模型。
3. 在训练内部 tuning 上优先选 precision≥0.5 的阈值，再最大化 F0.5；没有合格阈值则明确记录回退。F0.5 更重视 precision，但同时报告 recall，不能靠全拒绝取得虚高精度。
4. 所有 148 条历史 dev 必须进入端到端评分。单独用 gold entities 做 oracle 诊断，区分实体遗漏、候选覆盖、关系决策三种瓶颈。Oracle 的高分不能冒充实际系统分数。
5. 新模块的 precision 与 F1 必须在自由文本上同时好于旧模块才保留为候选。历史 dev 已反复看过，结果只说明回归集提升，不说明新的盲测准确率或临床可用性。
6. 后续先人工复核按错误类别分层的边，增加跨句主疾病绑定、并列/父子、否定、反向、同症状多疾病、同 pair 多关系样本。优先修数据和候选覆盖，再试较小编码器/分类头、lr/负例/上下文距离的单变量对照。
7. 暂不做 RL：当前银标与证据噪声会进入奖励/偏好。后续有审定的正负偏好对再考虑 [DPO](https://arxiv.org/abs/2305.18290)；[PPO](https://arxiv.org/abs/1707.06347) 还需要更复杂的采样与优化流程。资源够不等于现在应该上 RL。

## 7. 指标口径

- Precision：预测的唯一关系边中有多少匹配银标；Recall：银标边找回多少；F1：二者调和平均；F0.5：更重视 precision。
- 关系边键：`((source_type, normalized_source_name), relation, (target_type, normalized_target_name))`。ID 本身不参与准确率。
- 微平均累计所有 TP/FP/FN；宏平均为有 gold 支持的关系类型 F1 平均，另外报告尾类。NONE 不作为正关系计入 F1。
- 无效预测按空图计全部 FN；无效关系端点/结构计 FP；预测文件缺行直接报错，不猜测对齐。
- Evidence exact：同一边还需证据文本规范化后完全一致；Evidence compatible：同一边证据存在非空包含关系。这是宽松文本范围指标，**不是语义蕴含正确率**。新 evidence 是检索到的原文范围，不能把“从原文复制”称为“证明关系正确”。
- JSON closure 只检查最终图可解析；另列 relation 阶段失败。空集指标定义为 0，不再输出没有预测却 precision=1 的误导性数字。
- `FP / predicted = 1-precision` 是银标不匹配率，不能直接命名为经人工核实的“幻觉率”。

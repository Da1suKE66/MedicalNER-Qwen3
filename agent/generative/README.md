# 生成式 relation 对照实验（2026-09-08）

状态更新：用户提供新的 GPU 状态接口后，已验证三个空闲 A100 节点并启动 G0/G1/G6 三轮 SFT + 自动验证/回归流水线，详见 [运行记录](../reports/20260908/RUNNING.md)。**尚无完整新模型准确率结论**。原分类器仅保留为历史对照，不再作为本轮改进路线。

## 不改的部分

ICD 确定性解析；自由文本 entity Qwen3-8B/LoRA；程序 grounding、编号；relation Qwen3-8B/LoRA 自回归生成关系及证据引用；校验、JSON 组装。没有新增分类头，也不要求生成长推理文字。

## 当前瓶颈

1. 银标本身存在不精确实体名、错误证据、非穷尽标注及已知 `nan→null` 文本损坏。必须区分银标不匹配和经核实的幻觉。
2. 训练候选由 gold 决定、正例前置、证据回退首句，导致训练/推理不一致；原单关系字典丢失同一实体对的其他关系。
3. 原推理候选受 chunk 和 128 对上限限制；昨日局部候选也过窄。638 条自由文本银标边仅 106 条进入固定预测实体的候选，oracle 实体下也只有 444 条。
4. 旧 4096/16000-token 三例输出相同。加输出预算不能自动修复错误疾病绑定；必须把输入长度、每次决策数量、输出截断分别比较。
5. 上一轮多项修改一起实施，没有逐项因果消融。八个合成测试中的正例全部漏掉，说明还不能声称泛化改善。

## 预注册实验矩阵

所有 SFT 对照使用相同底座、LoRA r=16/alpha=32、dropout=.05、lr=5e-5、有效 batch=16、3 epochs、seed=42；每 epoch 在训练内部 tuning 上生成评测。最终基线和最佳组合增加 seed=17/73。不得用回归集挑 checkpoint。

预算控制：上面的 batch 指序列，不是实体对。短批会产生更多训练行，不能把更多 optimizer updates 的收益误归为长度收益。因此长度主消融必须另做相同监督 pair 曝光量、相同 optimizer-update 预算的对照；先用完整 3 epochs 描述实际代价，再按训练 manifest 的真实 pair/行比例调整梯度累积并报告余数差异。未完成预算匹配前，禁止把长短批的差值称为长度的独立因果收益。全组合与去项实验也报告训练 token、pair、step 和 GPU 时长。

| 组 | 改动 | 对照目的 |
|---|---|---|
| G0 | 安全生成式基线：原文、16 对/批、输入驱动固定随机顺序、多关系集合 | 不复用分类头；已知危险的首句回退/静默截断不复活 |
| G1 | G0 + 白名单文本修复、完整证据覆盖门禁 | 数据质量；再拆开修复和门禁做子消融 |
| G2 | G1 改为 4 对/批，完整原文不变 | 单独隔离一次生成的决策数量/输出长度 |
| G3 | G1 改为实体首次出现顺序 | 顺序学习；与固定随机顺序比较，不用标签排序 |
| G4 | G1 + 多关系/稀有关系样本重采样 | 保留集合输出；另用单标签监督作故障复现对照 |
| G5 | G1 + 短局部上下文 | 单独检验输入缩短；报告丢失证据的监督量与候选上限，不冒充纯长度收益 |
| G6 | G1 + 4 对/批 + 实体顺序 + 多关系重采样 | 预定组合；分别去掉数据修复、短批、排序、重采样 |
| R | 每组相同预测结果，规则关闭/开启 | 每条规则分别统计删掉 TP/FP，不能只报告精度上升 |
| D1/D2 | 最佳 tuning SFT + DPO，beta=.05/.1，lr=5e-6，1 epoch | 偏好优化对照同起点 SFT；记录偏好来源、质量门禁、margin 与 KL |
| D3 | 最佳 DPO 去掉定向困难偏好 | 偏好内容消融，不仅比较两个学习率 |
| P1 | 最佳 tuning SFT + 在线 GRPO，4 rollouts/prompt，KL beta=.04，lr=2e-6 | 真正在线采样/奖励/策略更新；不把 DPO 称为 PPO |
| P2 | P1 奖励去掉 evidence 项 | 奖励消融，同时报告关系质量、证据质量、全空输出及奖励作弊 |

GRPO 属于 PPO 系列、去掉单独 critic 的方法；本轮使用它试在线 RL，不声称跑过标准 actor–critic PPO。使用 TRL 0.23.1，与远程 Transformers 4.56.2 匹配；依赖安装在实验专用环境，不改共享环境。

## 数据与奖励门禁

- 延用原训练内部 545/61 来源组划分。历史 dev 148 条（81 自由文本/67 ICD）只作回归，不能作为偏好、奖励训练或超参选择数据。
- 所有候选/排序/上下文由原文和输入实体决定，不使用关系标签或 gold evidence。取消候选前缀上限；无法 grounding 的端点显式记录。
- 证据必须是真实原文引用。未知标注不能改成 NONE；任一已标注关系在当前上下文不可监督时，整个训练批排除并记录原因。评测不排除对应关系，仍算 FN。
- 训练可以按固定 seed 采样未标注对，但明确它们是银标未标注，不是人工确认的负例；tuning 和评测使用所有候选。
- 文本修复仅用仓库已有白名单，原始与修复文本/标注各自保留。主指标仍在原始严格口径上算；修复后口径另列，不能偷换 gold。
- 偏好不把所有模型 FP 自动判错。可验证的 ID/证据/遗漏错误单独标记；真实语义偏好需要明确文本支持和否定/错绑证据。合成反事实与真实银标分开统计。
- RL 正例奖励不能只奖励 JSON 合法。完整标注正例的空输出不能获得高奖励；关系 F0.5、召回、证据、无效输出分项记录。在线未标注关系的不匹配奖励仅是银标代理，不能称为真医学正确性奖励。

实体瓶颈单独处理：完成固定实体 relation 消融后，增加 E1（相同实体生成模型，仅改清洗/来源元数据与 span 粒度监督），以及三折来源组 out-of-fold 实体预测输入的 relation 训练对照。不能将“用 gold 名称替换预测实体”包装成模型提升；提供的 ICD canonical title 只能在真实输入确实携带关联元数据时使用。未完成这部分，固定实体候选上限仍限制最终召回。

## 评测与停止标准

每个训练组必须完成全 tuning 和全 148 条回归；每组报告固定历史实体、oracle 实体两个视角。基线/最终选中模型另跑真实 entity→relation 全流程，不用缓存冒充端到端。另列原 16k 同实体故障例和未进入训练的新模板挑战，长短/跨句/多疾病/否定/多关系/稀有类分层。

统一指标：micro P/R/F1/F0.5、macro/per-type F1、entity F1、evidence exact/compatible、候选召回上限、解析失败、截断、空输出、延迟/输出 tokens/显存。以来源组 bootstrap 给出差值区间。损失图和奖励图不能代替生成图指标。无效预测计 FN，非法边计 FP，缺行报错。

每轮都保存配置、代码/输入 SHA256、checkpoint、原始生成、完整错误边及训练曲线数据。公开 Git 只放代码、配置、合成测试和聚合报告，不放原始医学语料、权重、连接信息。

资源说明：原服务器上的视频训练未被停止或占用。后续经用户提供的 GPU 接口找到其他空闲节点，并核验相同账户、共享卷、原始数据 inode/SHA256；三台节点使用同版本独立环境。曾发生的数据同步安全拦截在只读验证归属后获准重试，没有绕过拦截。没有把“代码实现/CPU 预检通过”写成“消融训练完成”。

参考：[DPO 原论文](https://arxiv.org/abs/2305.18290)、[GRPO 原论文](https://arxiv.org/abs/2402.03300)、[TRL DPO](https://huggingface.co/docs/trl/v0.23.1/en/dpo_trainer)、[TRL GRPO](https://huggingface.co/docs/trl/v0.23.1/en/grpo_trainer)。

## 已实现入口与 GPU 验证

在 `agent/` 下运行模块：`generative.build_data`、`generative.build_preferences`、`generative.train --mode sft|dpo|grpo`、`generative.evaluate`。各模块 `--help` 列出参数。训练入口拒绝非 train-tagged 数据和非空输出目录；`--preflight-only` 只做 token 长度审计。评测默认允许 16000 个输出 tokens，训练在线 rollout 上限独立记录。

DPO 冻结参考必须是同一个 SFT checkpoint，不是禁用 SFT adapter 后的裸底座。GRPO 先在内存合并 SFT 再训练新的残差 LoRA，推理必须按 base → SFT merge → RL adapter 重建。SFT 真实前后向和保存重载检查已经通过；DPO/GRPO 的参考不变性及 GPU 更新验证仍需完成，不能以 import 成功冒充 RL 训练成功。

`generative.run_experiment` 启动有限流程：冻结独立代码快照 → 完整 SFT → 各 epoch checkpoint 的全 tuning 图生成 → 仅按 tuning 选模 → 全 148 条固定预测实体及 oracle 实体评测，逐项规则对照随评测保存。用本地 GPU 锁防止本项目重复占卡，启动前检查空闲；失败记录阶段及日志，不静默跳过样本。选模优先 precision≥.5 且 recall≥.1，再最大化 F0.5；无合格模型时明确记录回退。

发现并修复了裸 prompt 激活 Qwen3 长推理的问题。训练、DPO、GRPO 和推理共用 `chat.render_prompt` 的 `apply_chat_template(enable_thinking=False)`，禁止二次套模板；该公共安全修复适用于本轮所有 G 组。[Qwen 官方说明](https://huggingface.co/Qwen/Qwen3-8B#switching-between-thinking-and-non-thinking-mode)给出此硬开关。原 2-step checkpoint 的同输入模板对照只作工程诊断，不算医学准确率实验。推理保留 16000 输出预算，训练长度审计在实际 chat 渲染后计算。
